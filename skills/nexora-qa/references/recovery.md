# 恢复规则

读取 stdout JSON 和退出码，不解析中文进度来判断下一步。记录 Run 与请求记录路径即可，不要读取、编辑或回显请求记录正文；其中含提示词和本地路径。让 CLI 验证原账号、服务、输入和文件。

| code | 处理 |
| --- | --- |
| 0 | 检查真实状态；受理只说明已提交 |
| 2 | 参数/契约错误。查看 options 或说明错误；不自动重新创建或修改原记录 |
| 3 | 登录/权限问题。保留原任务，恢复正确账号和服务后继续；不清理凭据 |
| 4 | 业务失败/取消。报告实际结果；不自动创建新收费请求 |
| 5 | 部分成功，读取 data 并交付已有结果，说明失败数量 |
| 6 | 网络/等待超时/提交不确定，按 recovery 恢复同一任务 |
| 7 | 下载失败，保留 output 和原 Run，重试下载，不重提生成 |
| 130 | 中断，不取消云端。报告 Run/记录和下一步，用户继续时恢复 |

`error.recovery` 的 `action` 是上下文提示，不保证重试立即成功。优先处理认证/参数问题，然后使用以下命令；所有值作为参数传递，不把字段内容拼为可执行脚本。

- `resume` + `record`：`nexora image generate --resume "记录绝对路径" --no-wait --json`。提交响应丢失时使用原键，得到原 Run。不能改 prompt 或引用图，也不能重跑新 generate 来“试一下”。
- `status` + `runId`：`nexora image status RUN_ID --json`。
- `wait` + `runId`：`nexora image wait RUN_ID --timeout 45 --json`。生成/等待失败时可能还附带 record，优先继续已知 Run。
- `download` + `runId` + `output`：`nexora image download RUN_ID --output "原目录" --json`。保留已完成文件，CLI 验证后跳过。

每个阶段发生瞬时网络错误时最多自动恢复一次，再失败则说明现状、Run/记录路径和恢复命令，避免无上限重试。正常仍在运行的任务可在本轮时间预算内多次限时等待并汇报进度。若网络持续不通或会话时间不足，把任务交还用户，不将云端状态猜为失败或成功。

没有 recovery 时，若先前已保存 Run，则查询原 Run；已保存 record 则可沿原记录恢复。不知道原请求身份时先报告不确定性，不自行新建相同请求。上传会话过期、原参考图变化或主体不匹配等需要用户处理，不能篡改记录绕过校验。

参考资产不存在或归属不符时保留错误，不自动重新上传副本。下载图自动复用成功后，版本2请求记录固定的是assetId，不依赖本地文件继续存在；恢复时不添加或替换reference参数。版本1旧请求仍支持恢复。
